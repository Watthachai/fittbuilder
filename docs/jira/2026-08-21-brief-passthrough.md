## T29 · Brief ต้องเดินทางไปถึงเทิร์น build

**Epic:** E7 · Generation Quality — **Type:** Bug — **Priority:** Highest — **Status:** ✅ Done (`ef1dfb9`)

### ที่มาของปัญหา

`buildFromDocs` ส่งประโยคตายตัวเป็น prompt:

> "สร้าง web demo ตามเอกสาร BRD/PRD ที่แนบมา ให้ครบทุกหน้าจอและตรง design direction ที่ระบุ"

แล้วแนบแค่ BRD/PRD ที่เอเจนต์เขียนสรุปไว้ ซึ่งยังโดน `truncateDoc` ตัดเหลือ 6,000 ตัวอักษรโดยเก็บเฉพาะบรรทัดที่เป็นหัวข้อ/ตาราง/bullet

เอกสารธุรกิจไม่มีเหตุผลจะจด `#DCFF00`, `aspectRatio: '640 / 820'` หรือ URL วิดีโอ — **รายละเอียดพวกนี้ตายที่ขั้นสรุป ไม่ใช่ขั้นเขียนโค้ด**

อาการสี่อย่างมาจากรากเดียวกัน:

| อาการ | กลไก |
|---|---|
| วิดีโอไม่ขึ้น กลายเป็น CSS gradient | URL ไม่เคยไปถึง |
| ไม่เป็นคอลัมน์อีเมล 640px | ข้อจำกัดเลย์เอาต์ไม่เคยไปถึง |
| ข้อความกลายเป็นไทยทั้งหน้า | กฎภาษาอ่านจาก "เอกสาร" ซึ่งเขียนเป็นไทยเสมอ |
| โผล่เนื้อหาที่ไม่ได้สั่ง (เช่น "Cohort 4") | ไม่มี copy จริงให้ใช้ กฎ mock data จึงแต่งขึ้น |

### สิ่งที่ทำ

- `buildSpecContext` รับ `brief` เพิ่ม พิมพ์เป็นบล็อก `[0]` **นำหน้า** BRD/PRD พร้อมประโยคลำดับความสำคัญ: ค่าที่ระบุเป๊ะใน brief (สี · ขนาด · URL · ข้อความ · ภาษา) คือของจริง เอกสารด้านล่างเป็นบทสรุปของมัน ไม่ใช่ตัวแทน
- `truncateBrief` ตัดจาก**ตรงกลาง** ไม่ตัดท้าย — spec จบด้วย palette กับ font stack เสมอ และ `truncateDoc` เก็บ "บรรทัดโครงสร้าง" ทิ้งความเรียง ซึ่งกลับหัวกลับหางสำหรับ brief ที่เนื้อสำคัญอยู่ในความเรียง (ในทางปฏิบัติไม่ถูกตัดเลย เพราะช่องพิมพ์จำกัดไว้ต่ำกว่างบอยู่แล้ว)
- `originalBrief()` ใน Studio อ่านข้อความแรกของผู้ใช้ ส่งไปทั้งสามทางเข้า: Express, "สร้างใหม่จากเอกสาร", และทางวาง BRD/PRD
- กฎภาษายึด **brief** ไม่ใช่เอกสาร
- กฎ DESIGN QUALITY ประกาศตัวเป็น**ค่าตั้งต้นสำหรับสิ่งที่ brief ไม่ระบุ** — คอลัมน์ 640px ที่สั่งมาตรงๆ จะไม่โดนยัด navbar แบบ SaaS ทับ
- mock data แต่งได้เฉพาะช่องที่ brief เว้นไว้

### ผลลัพธ์ที่ผู้ใช้เห็น

วาง spec ที่มีค่าเป๊ะแล้วได้ของตามนั้น — สีตรง ขนาดตรง วิดีโอเล่น ข้อความไม่ถูกแปล

### เงื่อนไขการตรวจรับ

- [x] วาง spec ที่ระบุ URL วิดีโอ → วิดีโอเล่นจริงในพรีวิว พร้อม `crossOrigin="anonymous"`
- [x] spec ที่ระบุ `max-w-[640px]` → ได้คอลัมน์ 640px ไม่ใช่หน้าเต็มจอ
- [x] brief อังกฤษ + BRD/PRD ไทย → ข้อความที่ผู้ใช้เห็นเป็นอังกฤษทุกไฟล์
- [x] โปรเจกต์เก่าที่ไม่มี brief → context เหมือนเดิมเป๊ะ ไม่มีบล็อก `[0]` โผล่

## T30 · ช่องพิมพ์รับ 20,000 ตัว และเตือนก่อนเต็ม

**Epic:** E7 · Generation Quality — **Type:** Bug — **Priority:** High — **Status:** ✅ Done (`0d0a535`)

### ที่มาของปัญหา

`maxLength` หยุดรับเงียบๆ ตรงตัวที่ 10,000 — ไม่มี error ไม่มีคำเตือน และเพราะ spec มักจบด้วย palette กับ font stack **ครึ่งที่หายคือครึ่งที่สำคัญที่สุดพอดี**

เลขนี้เคยถูกเขียนแยกกันสี่ที่ (textarea หน้าแรก · textarea แชท · `/api/agent` · `/api/generate`) **ตัวที่แคบสุดจึงเป็นคนกำหนดลิมิตจริงโดยไม่มีใครตั้งใจ** — และเพิ่ง drift ไปแล้วครั้งหนึ่งตอน `brief` รับ 20,000 แต่ `prompt` ยังรับ 10,000

### สิ่งที่ทำ

- `lib/limits.ts` เป็นเลขตัวเดียวที่ทั้งสี่ด่านอ่านร่วมกัน (`MESSAGE_MAX_CHARS = 20_000`)
- ตัวนับเปลี่ยนเป็นสีเตือนที่ 90% (18,000) ก่อนถึงเพดาน
- เทสต์กันไม่ให้ไฟล์ไหนกลับไปตั้งเพดานของตัวเอง

### เงื่อนไขการตรวจรับ

- [x] วาง spec 7,972 ตัว → ตัวนับขึ้น `7972/20000` เนื้อครบ ไม่ถูกตัด
- [x] ทั้งสี่ด่านอ่านเลขจาก `lib/limits.ts` ไม่มี literal เหลือ
- [x] พิมพ์เกิน 18,000 → ตัวนับเปลี่ยนสีก่อนถึงเพดาน

## T31 · lucide ไม่มีไอคอนแบรนด์แล้ว

**Epic:** E7 · Generation Quality — **Type:** Bug — **Priority:** Medium — **Status:** ✅ Done (`42b797b`)

### ที่มาของปัญหา

พบตอนทดสอบ T29 บน localhost — spec สั่ง `import { Facebook, Twitter, Instagram, Youtube, Linkedin } from "lucide-react"` แล้วได้จอขาว:

```
does not provide an export named 'Facebook'
```

ตรวจแล้ว **lucide-react 1.33.0 ไม่มีไฟล์ไอคอนแบรนด์เหลือสักตัว** (แกะ tarball ยืนยัน) และการ import ของที่ไม่มี**ไม่ได้ตกไปหาไอคอนสำรอง** — มัน throw แล้วทั้งแอปดับ แถวไอคอนโซเชียลแถวเดียวล้มทั้งหน้า

prompt แนะนำ lucide-react เป็นตัวเลือกที่ verify แล้ว แต่ไม่เคยบอกว่ามีของที่หายไป — **brief ไหนที่พูดถึงไอคอนโซเชียลก็เจอเหมือนกันหมด** และ brief ที่เขียนไว้ตอน lucide ยังมีไอคอนพวกนี้ก็ยิ่งสั่งตรงๆ ให้ import

นี่คือผลข้างเคียงที่คาดได้ของ T29: เมื่อ brief มีอำนาจเหนือกฎบ้าน มันก็ตามไปชนของที่ไลบรารีไม่มีแล้ว

### สิ่งที่ทำ

เขียนเส้นแบ่งให้ชัดในกฎข้อ 7: **brief กำหนดว่าไอคอนควร "หน้าตายังไง" ไม่ได้กำหนดว่า export ที่ไม่มีอยู่นั้นมีอยู่** — ให้วาดเป็น inline SVG แทน

### เงื่อนไขการตรวจรับ

- [x] spec ที่สั่ง import ไอคอนแบรนด์จาก lucide → ได้ inline SVG แอปไม่ดับ
- [ ] *(ยังไม่ได้ยืนยันหลังแก้ prompt)* build ใหม่จาก spec เดิม → ไม่มี error ตั้งแต่รอบแรก
