## วิธีรัน

### A. เทสต์อัตโนมัติ (ฟรี ไม่ยิง API)

```bash
npx vitest run lib/__tests__/brief-context.test.ts
```

ครอบ R2 · R3 · R6 และการเดินสายฝั่ง client/API (20 เทสต์)

**เกณฑ์ผ่าน:** 20/20 ผ่าน

### B. Gate เต็ม

```bash
npx tsc --noEmit && npm run lint && npx vitest run && npm run build
```

**เกณฑ์ผ่าน:** tsc เงียบ · lint เงียบ · 321/321 · build สำเร็จ

### C. ยิงโมเดลจริง (ไม่ผ่าน HTTP)

เขียนไฟล์ชั่วคราวที่ประกอบ system prompt ด้วย `buildGenerationSystemPrompt(buildSpecContext({ brief, brd, prd }))` แล้วเรียก `streamText` ตรง — เร็วกว่าขับ UI และแยกได้ว่าปัญหาอยู่ที่ prompt หรือที่การเดินข้อมูล

**เกณฑ์ผ่าน:** ผลลัพธ์มีครบ — URL วิดีโอทุกตัว · `crossOrigin` · `max-w-[640px]` · `640 / 820` · hex ทุกค่า · ข้อความอังกฤษ · ไม่มี `@tailwind` at-rule
**ผลจริง 2026-08-21:** 14/14

> ⚠️ probe ที่เขียนว่า `/@tailwind|@apply/` จะ match `<script src=".../@tailwindcss/browser@4">` ใน `index.html` ด้วย ต้องผูกกับต้นบรรทัด: `/^\s*@(tailwind|apply)\b/m`

### D. ขับ UI จริง — เคสที่จับบั๊กได้จริง

1. `npm run dev` แล้วเปิด `http://localhost:3000`
2. วาง spec ทั้งก้อนในช่องหน้าแรก → **ตรวจว่าตัวนับตรงกับความยาวจริง** (R5)
3. กด "สร้างเลย" → เลือกประเภทที่ระบบตรวจให้
4. รอ Express: BRD → PRD → build
5. **ดูพรีวิวจริง** ไม่ใช่แค่ข้อความสรุปในแชท

**เกณฑ์ผ่าน:**
- hero เป็นวิดีโอ ไม่ใช่ gradient
- เนื้อหาอยู่ในคอลัมน์แคบ ไม่เต็มจอ
- ข้อความบนจอเป็นภาษาเดียวกับ brief
- ไม่มีแถบ error สีแดงเหนือพรีวิว

6. ตรวจโค้ดจากฐานข้อมูล:

```bash
node scripts/db-query.mjs "select files::text from fittbuilder_projects where id='<project-id>'" > /tmp/proj.json
grep -cF "hf_20260419_064822" /tmp/proj.json   # ต้องได้ > 0
```

## สิ่งที่พิสูจน์แล้ว

- brief เดินทางครบทั้งสามทางเข้า build (Express · rebuild-from-docs · paste-BRD/PRD) — **เดินสายพิสูจน์ด้วยเทสต์ ผลลัพธ์พิสูจน์ด้วยการรันจริงหนึ่งรอบเต็ม**
- ค่าที่ระบุเป๊ะใน brief ออกมาในโค้ดจริง 17/17 ค่า
- ภาษาไม่ถูกแปล 17/17 ไฟล์ (ไทยเหลือเฉพาะ `data-fitt-screen` ซึ่งเป็นป้ายซ่อนสำหรับใบเสนอราคา — ถูกต้องตามที่ออกแบบ)
- โปรเจกต์เก่าที่ไม่มี brief ได้ context เดิมเป๊ะ

## สิ่งที่ยังไม่ได้พิสูจน์

| | ทำไมถึงยังไม่ได้ทำ |
|---|---|
| กฎ lucide (T31) กันบั๊กได้ตั้งแต่รอบแรก | แก้ prompt หลังจากที่ build ผ่านไปแล้ว ยังไม่ได้ build ใหม่จาก spec เดิม |
| brief ที่ยาวเกิน 20,000 จริงๆ | `truncateBrief` ผ่าน unit test แต่ยังไม่เคยเจอ input ขนาดนั้นจากผู้ใช้จริง |
| spec ภาษาอื่นที่ไม่ใช่ไทย/อังกฤษ | ยังไม่มีเคส |
| brief ที่ขัดกับ BRD/PRD ตรงๆ | ยังไม่มีเคสที่เอกสารถูกแก้จนขัดกับ brief แล้วดูว่าอันไหนชนะจริง |

## สิ่งที่รู้แล้วว่าทำไม่ได้

`@tailwind base;` ใน `index.css` — โปรเจกต์ที่ generate ใช้ Tailwind ผ่าน CDN เขียน build-time directive แล้ว dev server พัง กฎ prompt กันไว้แล้วและโมเดลเลี่ยงถูก **spec ที่สั่งแบบนี้จะได้ผลลัพธ์ที่หน้าตาเหมือนกัน แต่โค้ดไม่ตรงตัวอักษร** — เป็นข้อจำกัดของ runtime ไม่ใช่บั๊ก
