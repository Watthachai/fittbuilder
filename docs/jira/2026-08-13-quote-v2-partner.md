## บริบท — ทำไมต้องมีรอบนี้

ใบเสนอราคาที่ทำไว้เมื่อ 5 ส.ค. (T14–T17 ในเอกสารก่อนหน้า) คิดได้แค่ **ราคางานพัฒนาครั้งเดียว**: ขนาดงาน → แรงงาน (วัน) → ราคาต่อวัน → VAT

สิ่งที่ขาดคือทุกอย่างที่อยู่ **หลังตัวเลขนั้น** และเป็นสิ่งที่ทำให้เอกสารเป็นสัญญาได้จริง:

| ขาด | ผลที่เกิด |
|---|---|
| งวดชำระ | ต้องพิมพ์เป็นข้อความในช่อง "เงื่อนไข" ตัวเลขไม่ผูกกับยอดจริง แก้ราคาแล้วลืมแก้งวด |
| เงื่อนไขตรวจรับ | ข้อตกลง "ส่ง UAT → จ่าย 60% → เงียบ 30 วัน = ตรวจรับแล้ว → จ่าย 40%" ต้องหวังว่าคนจะพิมพ์ครบและพิมพ์ถูก |
| ค่าบำรุงรักษา (MA) | ไม่มีที่ให้เสนอเลย ต้องทำเอกสารแยกหรือพิมพ์แปะท้าย |
| หัวกระดาษ | เป็น textarea ล้วน ไม่มีโลโก้ — partner เอาไปใช้กับลูกค้าตัวเองไม่ได้ |

**หลักการที่ยึดตลอดรอบนี้:** ตัวเลขทุกตัวบนกระดาษต้อง *คำนวณจากฟิลด์จริง* ไม่ใช่ข้อความที่พิมพ์ซ้ำ — ข้อสัญญาที่พิมพ์ออกมาจึงขัดกับตารางงวดชำระไม่ได้

**ปัญหา / ที่มา**
เงื่อนไขการชำระเงินอยู่ในบรรทัดเดียวของ `DEFAULT_TERMS` ที่คนต้องพิมพ์เอง แปลว่าถ้าแก้ราคาหลังพิมพ์เงื่อนไขไปแล้ว เอกสารจะบอกยอดสองยอดที่ไม่ตรงกัน — และคนที่เจอปัญหานี้คือคนที่เซ็นสัญญา ไม่ใช่คนที่ทำเอกสาร

**สิ่งที่ทำ**
- เพิ่มสี่บล็อกใน `QuoteDoc` (`lib/quote.ts`): `payment` (งวดชำระเป็น % ของยอดรวม), `acceptance` (เงื่อนไขตรวจรับ), `ma` (ค่าบำรุงรักษา), `brand` (หัวกระดาษ)
- `paymentSchedule()` แปลง % เป็นเงิน โดยให้งวดสุดท้ายรับเศษที่ปัดไว้ — คอลัมน์จำนวนเงินบวกกันได้เท่ากับยอดรวมทั้งสิ้นเป๊ะ (วินัยเดียวกับที่ `quoteTotals` ปัดทีละบรรทัด) แต่ทำได้เฉพาะตอน % รวมได้ 100 เท่านั้น
- `maintenanceTotals()` บังคับขั้นต่ำ ฿15,000/module/เดือน ที่ฟังก์ชันเดียว panel กับกระดาษจึงเห็นตัวเลขเดียวกันเสมอ
- Preset งวดชำระ 3 แบบ: `presetUat()` (60/40 แบบที่ตกลงกับ FITT Code Runner), `presetSigning()` (ลงนาม 60 / ส่งมอบ 40), `presetEqual(n)` (แบ่งเท่ากัน n งวด เศษ % ตกที่งวดสุดท้าย)
- ไฟล์ใหม่ `lib/quote-clauses.ts` — `acceptanceClauses(doc)` สร้างข้อสัญญาจากตัวเลขของเอกสารเอง ข้อความอ้างอิงกันด้วยเนื้อหา ไม่ใช่เลขข้อ
- `parseDoc()` backfill ทั้งสี่บล็อกให้ใบเก่า
- เทสต์ใหม่ 20 เคสใน `quote.test.ts` และ `quote-clauses.test.ts`

**ผลลัพธ์ที่ผู้ใช้เห็น**
แก้ตารางงวดชำระแล้วเปอร์เซ็นต์และจำนวนเงินในข้อสัญญาเปลี่ยนตามทันที ไม่มีทางที่เอกสารจะบอกสองยอดที่ไม่ตรงกัน

**Acceptance criteria**

- [x] % รวมได้ 95 → `balanced: false` และ **ไม่** ยัดเศษให้งวดสุดท้าย
