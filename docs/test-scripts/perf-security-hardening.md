# Test Script — แก้ต้นเหตุระบบล่ม และตรวจความปลอดภัย (v0.49.0)

คู่กับ `docs/jira/2026-08-18-perf-security-hardening.md`

เอกสารนี้บอกสองอย่างที่ต่างกัน และอย่าสับสน:
**อะไรพิสูจน์แล้ว** (มีหลักฐาน วันไหน ด้วยวิธีไหน) กับ **อะไรยังไม่พิสูจน์** (ต้องมีคนกดจริง)

รอบนี้ต่างจากรอบก่อนตรงที่เกณฑ์ผ่านส่วนใหญ่เป็น **ตัวเลขที่วัดได้** ไม่ใช่ "ดูแล้วถูก" — งานทั้งรอบเป็นเรื่องปริมาณ ถ้าวัดไม่ได้ก็พิสูจน์ไม่ได้ว่าแก้แล้ว

### R4 + R5 · push/pop ถูกต้องและมีด่านกั้น (18 ส.ค.)

รันใน transaction ที่ rollback ทั้งหมด — ฐานข้อมูลจริงไม่ถูกแตะ

| ขั้น | ผล |
|---|---|
| ก่อน push | `history_count = 1` |
| `push(pid, '{"probe.txt":"hello"}')` | คืน `2` |
| `pop(pid)` | คืน `{"probe.txt": "hello"}` — ตรงกับที่ใส่เข้าไป |
| หลัง pop | `history_count = 1` · `files` เป็นสแนปช็อตที่ถอนมา |
| pop ในนาม uid แปลกหน้า | `ERROR: project ... not found or not readable` |

### ทฤษฎีที่ทดสอบแล้วผิด — RLS ไม่ใช่ต้นเหตุ

เบนช์มาร์กที่ 2,000 แถว: `auth.uid()` ต่อแถว = **32.4 ms** · `(select auth.uid())` = **32.9 ms** — ไม่ต่างกัน
บันทึกไว้เพื่อไม่ให้มีคนเสียเวลาลองซ้ำ การห่อ `auth.uid()` ไม่ช่วยที่นี่ เพราะ helper function ถูกเรียกต่อแถวอยู่ดี

## ยังไม่พิสูจน์ — ต้องมีคนกดจริง

### R9 · Undo ผ่าน UI (สำคัญที่สุดในรายการนี้)

เทสต์อัตโนมัติพิสูจน์ได้แค่ว่า **ฟังก์ชันในฐานข้อมูลถูกต้อง** ไม่ได้พิสูจน์ว่า **สตูดิโอเรียกมันถูกจังหวะ** — และ `withHistory` ตอนนี้ยิงคำสั่งแบบไม่รอผล (fire-and-forget) ซึ่งเป็นจุดที่ลำดับเวลาผิดได้

ขั้นตอน (`npm run dev`):

1. เปิดโปรเจกต์ที่มีไฟล์อยู่แล้ว → เปิด DevTools › Network › กรอง `fittbuilder_projects`
   **ตรวจ:** คำขอ `select` ต้องไม่มีคำว่า `history` ใน query string และขนาด response ต้องเล็กลงชัดเจน
2. แก้โค้ดหนึ่งไฟล์ผ่าน editor แล้วรอให้บันทึก
   **ตรวจ:** เห็นคำขอ `rpc/fittbuilder_history_push` หนึ่งครั้ง · ปุ่ม Undo เปลี่ยนเป็นกดได้
3. กดปุ่ม Undo
   **ตรวจ:** เห็น `rpc/fittbuilder_history_pop` · ไฟล์กลับไปเนื้อหาเดิม · พรีวิว rebuild เอง
4. กด ⌘Z ซ้ำจนสุด
   **ตรวจ:** ปุ่มเทาลงเมื่อ `history_count` ถึง 0 · ไม่มี error ใน console
5. สั่ง generate หนึ่งรอบ แล้วกด Undo
   **ตรวจ:** กลับไปสถานะก่อน generate ไม่ใช่กลางทาง

### R8 · ช่องโหว่ host-header — ยังไม่แก้

ต้องได้ค่าโดเมนจริงของ prod และ sandbox ก่อน แล้วตั้ง `PUBLIC_SITE_URL` ใน Cloud Build trigger ทั้งสองตัว

## หลัง deploy ขึ้น dev/main แล้วต้องดูอะไร

1. **ลำดับต้องถูก** — migration ก่อน แล้วค่อย deploy โค้ด (โค้ดอ่าน `history_count` แล้ว) ถ้าสลับลำดับ สตูดิโอจะเปิดโปรเจกต์ไม่ได้ ข้อมูลไม่หายแต่ระบบล่ม
2. **บอกให้คนที่เปิดค้างรีเฟรช** — ดู R10
3. **วัดซ้ำหลังใช้งานจริงหนึ่งวัน** — `pg_stat_statements` ควรเห็น upsert ของ `fittbuilder_projects` หลุดจาก 200 ms ลงมามาก ถ้าไม่ลง แปลว่ายังมีตัวขนหนักอื่นที่ยังไม่เจอ
4. **ถ้าต้องถอย** — revert commit `27d94be` แล้ว deploy ใหม่ได้ทันที คอลัมน์ `history` และข้อมูลยังอยู่ครบ ไม่ต้องแตะฐานข้อมูล
